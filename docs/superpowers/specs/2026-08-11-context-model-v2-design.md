# Context model v2 — memory index, freshness, and skill attachments

wondev's starter pack teaches a shape for agent context. A real project — a 13-service
meta-repo with an Obsidian dev-guide vault — independently arrived at a stricter shape and
ran it in production. Three of the things it does cannot be expressed in `.wondev/` today,
so compiling that project into wondev would silently discard them.

This spec closes those gaps. It is the prerequisite for `wondev adopt` (a separate spec):
a reverse-compiler is only as faithful as the target format allows.

## What is missing today

| Pattern proven in the source project | Fate in `.wondev/` as of 0.1.1 |
| ------------------------------------ | ------------------------------ |
| `skills/<name>/references/*.md` — progressive-disclosure attachments | Dropped. `findSkillFiles` returns only `SKILL.md`, and `Skill` has no field to hold more. |
| Freshness frontmatter: when a doc was last checked, and *against what* | Dropped. The parser reads `title`/`description`/`always`/`globs`; everything else is discarded. |
| An index carrying per-note token cost and a "read this when" trigger | No equivalent. The rule "a new note must add an index row" is unenforceable. |

The third is the load-bearing one. The index is not a table of contents; it is the mechanism
that makes a large vault affordable. It states the token price of each note and the condition
under which paying it is worthwhile, so an agent loads three notes instead of thirty. wondev
has the raw material for this — `description` and `always` — and does nothing with it.

## Not a schema bump

`SOURCE_SCHEMA_VERSION` stays at 1.

`schema.ts` states the rule: *"Bump when authored files must change."* Nothing authored must
change. Every new frontmatter key is optional, attachments are additive, and the index is
opt-in. A schema-1 project parses identically under this release.

Bumping would make `assertSchemaCurrent` refuse every existing project and demand a
`wondev migrate` that has nothing to migrate. The version stamp exists to enable migrations,
not to advertise that the code changed.

Generated bytes do change, so this is a **MINOR** release under `docs/versioning.md`.

## 1. Memory index

### Configuration

```yaml
# .wondev/wondev.yaml
index:
  file: docs/dev-guide/Beranda.md   # where to write the table; omit to generate no index
  budget: 8000                       # optional ceiling on always-on context, in tokens
  columns:                           # optional extra columns, sourced from `extra`
    - { key: owner, label: Owner }
```

Every key is optional. With no `index.file`, wondev behaves exactly as it does now — this
whole feature is inert until a project asks for it.

### Mechanism

The index is a `RenderedFile` with `mode: 'region'` at `index.file`, carrying the target name
`index`. It needs no new machinery: `planWrites` already handles region mode additively,
`replaceRegion` preserves everything outside the markers, the manifest already tracks the
hash of the owned span, `check` already reports drift, and `removeOwned` already strips a
region without deleting the surrounding file.

This is why the index is written *outside* `.wondev/` rather than into a source file.
wondev's central invariant is that `.wondev/` is authored and everything else is generated;
`check` compares the two. A source file that `build` mutates would blur that line for the
one command whose entire job is to detect drift.

### Content

Two tables, because the cost model differs:

```markdown
## Always loaded

Injected into every target's context on every turn.

| Note | ≈tok | Checked | When to read |
| ---- | ---- | ------- | ------------ |
| Architecture | 0.6k | ✓ 2026-08-10 | — |

**Always-on total: ≈1.4k tokens** (budget 8k)

## On demand

| Note | ≈tok | Checked | When to read |
| ---- | ---- | ------- | ------------ |
| [[decisions/0001-single-process]] | 0.3k | | Asking why the architecture is shaped this way. |
```

- Ordering matches `loadMemory`: always-on first, then slug-alphabetical. Stable output is
  what makes golden-file testing meaningful.
- **Note** links with `[[slug]]`, the syntax wondev already validates and Obsidian already
  resolves.
- **≈tok** is `ceil(chars / 4)`, rendered as `0.6k`. No tokenizer dependency: wondev ships
  one runtime dependency and an estimate is what the `≈` already promises.
- **Checked** shows `✓ <date>` from `verified`. The column is emitted only when at least one
  memory doc carries `verified`, so projects that never use it get no empty column. That
  condition is a pure function of the project, so output stays deterministic.
- **When to read** is `description`. Empty when absent.
- The budget parenthetical appears only when `index.budget` is set.

### Budget enforcement

When `index.budget` is set and the always-on estimate exceeds it, `check` **fails** and names
the three largest contributors.

When it is unset, nothing is enforced. This is deliberate and is the point the release
contract exists to protect: shipping a default budget would fail `check` in every project
that upgrades and happens to sit above the number wondev picked, on a MINOR bump nobody read
the notes for. A user who wants the discipline opts into it.

`build` never enforces the budget. It reports the always-on total once per run and proceeds;
refusing to build over a documentation threshold would strand a project with no way to
inspect its own output.

## 2. Freshness and frontmatter passthrough

`MemoryDoc` gains three fields:

```ts
/** Date this document was last checked against the code, ISO `YYYY-MM-DD`. */
verified?: string;
/** What it was checked against — the evidence, not just the date. */
verifiedAgainst?: string;
/** Frontmatter keys wondev does not interpret, preserved verbatim. */
extra: Record<string, unknown>;
```

`verified` must match `YYYY-MM-DD`; anything else is a warning naming the file, and the field
is ignored. A malformed date must not become a `✓`.

`verifiedAgainst` is free text and is deliberately **not** given a column of its own — a
sentence of evidence would swamp the row. It is shown by `wondev doctor`, which is where
someone asking "is this document trustworthy?" is already looking.

`check` reports memory docs with no `verified` as **warnings**, never errors. An unverified
document is not a defect; it is a document nobody has audited yet, which is the normal state
of most documentation. Erroring would make the feature unusable on the day it ships.

### Where `extra` surfaces

`extra` exists so a project can carry its own vocabulary without wondev learning it. Unknown
keys are **never** injected into any target's frontmatter: `.mdc` and `.md` rule files are
parsed by other people's tools, and posting arbitrary keys into them risks breaking a parser
wondev does not control.

Instead a project opts them into the index:

```yaml
index:
  file: docs/dev-guide/Beranda.md
  columns:
    - key: owner        # frontmatter key to read from `extra`
      label: Owner      # column heading
```

Each configured column is appended after the built-in ones. A doc missing that key gets an
empty cell. Values are stringified and their `|` characters escaped, so a stray pipe cannot
break the table. Columns are emitted in configured order; an empty `columns` list behaves as
if absent.

## 3. Skill attachments

### Loading

Any `*.md` file under `.wondev/skills/<name>/` other than `SKILL.md` becomes an attachment:

```ts
export interface Attachment {
  /** Path relative to the skill directory, forward-slashed, e.g. `references/query.md`. */
  relPath: string;
  content: string;
}
```

`Skill` gains `attachments: Attachment[]`, sorted by `relPath`.

**Markdown only.** Non-`.md` files in a skill directory are ignored with a warning naming
the file. Two reasons: `wholeContent()` prepends an HTML comment header to every generated
file, which corrupts anything that is not markdown; and reading arbitrary bytes as UTF-8
would mangle them silently. A rule that refuses loudly beats one that damages quietly.

The flat `skills/<name>.md` form has no directory and therefore no attachments. It stays
supported and unchanged.

### Rendering

**`claude` engine** — writes each attachment to `<skillsDir>/<name>/<relPath>`, `mode: 'whole'`,
tracked in the manifest like any other generated file. Deleting an attachment from `.wondev/`
removes it from the output on the next build, via the existing stale-file sweep.

**Flat targets** (`single-file`, `rule-dir`) — never inline attachment content. `skillSection`
appends a pointer:

```markdown
**Reference material** — read on demand, not included here:
- `.wondev/skills/graphify/references/query.md`
```

Inlining would be actively wrong. Reference files exist precisely so they stay out of context
until needed; `flattenProject` already copies every skill body into `AGENTS.md`, and adding
seven reference files per skill on top of that would inflate the file whose cost is paid on
every single turn. The renderer already states this principle at `claude.ts:53` — *"An index,
not the bodies"* — and this extends it one level down.

The pointer names a real path in the user's repository, so an agent that wants the material
can simply read it.

## 4. Slug normalization

`flatSlug` currently maps `/` and `\` to `-`. It will also collapse whitespace runs to `-`.

A vault written for humans uses titles like `Alur Live Map.md`. As a memory slug that is
legal today — `NAME_PATTERN` constrains only skills and commands — but it produces
`memory-Alur Live Map.mdc` on rule-dir targets: a generated filename with spaces, committed
to someone's repository.

Memory slugs stay unconstrained. Adding a pattern would be a breaking change for a shape
wondev currently accepts, and `adopt` can normalize on import instead.

## 5. Error handling

| Situation | Level | Behaviour |
| --------- | ----- | --------- |
| `index.file` outside the project root | error | Rejected by the same `isInsideRoot` guard as target paths |
| `index.file` set, file does not exist | — | Created, containing only the region |
| `index.file` exists with hand-written prose | — | Region appended; prose untouched (`action: 'adopt'`) |
| `index.budget` not a positive integer | error | Config refused at load |
| `index.columns` entry missing `key` or `label` | error | Config refused at load |
| `extra` value containing `\|` | — | Escaped so the table cannot break |
| Always-on total over budget | error in `check` | Names the three largest contributors |
| `verified` not `YYYY-MM-DD` | warning | Field ignored; no `✓` |
| Memory doc with no `verified` | warning in `check` | Reported, never fatal |
| Non-`.md` file in a skill directory | warning | Ignored |
| Attachment path escaping the skill dir | error | Cannot occur from `listFilesRecursive`, re-checked anyway |

## 6. Testing

- **Unit** — token estimate rounding; index table for the four shapes (no memory, no
  verified anywhere, some verified, over budget); `verified` date validation; attachment
  discovery including the non-`.md` warning and the flat-skill-file case.
- **Golden** — `test/fixtures/golden/` regenerated. A skill with attachments is added to the
  fixture project so the claude engine's attachment output and the flat targets' pointer
  block are both pinned. Diffs here are a deliberate MINOR decision, per `docs/releasing.md`.
- **Region behaviour** — an `index.file` with pre-existing prose keeps it across a build,
  loses only the region on `clean`, and reports drift when the region is edited by hand.
- **Budget** — `check` passes with no budget configured regardless of size; fails once a
  budget below the total is set. This is the regression test for the "do not break every
  downstream CI" rule.
- **Custom columns** — a configured column reads from `extra`, renders an empty cell for docs
  lacking the key, and escapes a value containing `|` without breaking the table.

## 7. Release impact

MINOR. Generated bytes change for every project: the attachment pointer block alters skill
sections on flat targets, and `flatSlug` alters filenames for slugs containing whitespace.
Projects with no attachments and no whitespace slugs see no output change, but the release is
MINOR regardless — the renderer changed, and `docs/versioning.md` keys on that, not on
whether a particular project notices.

Docs to update: `README.md` (index and attachments), `docs/versioning.md` (no new rule, but
the frontmatter table grows), `CHANGELOG.md`.

## Out of scope

Deferred to the `wondev adopt` spec:

- Reading `CLAUDE.md` / `AGENTS.md` / `.claude/skills/` / `.cursor/rules/` back into `.wondev/`.
- Mapping project-specific frontmatter vocabulary (e.g. Indonesian `diperiksa:`) onto
  `verified` during import.
- Slug normalization of human-titled vault notes on import.
- Multi-repo projects: 7 of the 13 service repos carry their own `CLAUDE.md`. wondev operates
  on one root, and whether `adopt` should span sibling repositories is that spec's question.

Explicitly not planned:

- A real tokenizer. The estimate is honest about being one.
- Three-way merge of index prose. The region boundary is the whole point.
